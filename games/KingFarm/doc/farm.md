# 作物倒计时管理系统 需求规格说明书

## 1. 概述
一个基于浏览器的单页面应用，用于管理作物成熟与浇水倒计时。数据持久化于 `localStorage`，支持增删改查、浇水加速、排序、导入导出，并具备商业级视觉渲染和移动端适配。

## 2. 数据模型
每行数据包含以下字段：

| 字段 | 类型 | 说明                          |
|------|------|-----------------------------|
| `id` | string | 唯一标识，自增id                   |
| `user` | string | 用户名称，可编辑，允许为空               |
| `cropType` | enum | `'16h'` 或 `'32h'`           |
| `matureCountdown` | number | 成熟倒计时，剩余秒数（不允许负数，归零即为“已成熟”） |
| `waterCountdown` | number | 浇水湿润倒计时，剩余秒数（不允许负数）         |
| `createOrder` | number | 递增序号，用于默认排序（按行添加先后）         |
| `createdAt` | number | 创建时间戳（毫秒），用于恢复数据时的稳定性       |

### 计算属性（运行时动态计算）
- **水分干枯时间** = `当前时间 + waterCountdown`，格式 `YYYY-MM-DD HH:mm:ss`  
- **预计成熟时间** = `当前时间 + matureCountdown`，格式 `YYYY-MM-DD HH:mm:ss`  
- **作物总成熟时长**：16h 作物 = `57600s` (16×3600)，32h 作物 = `115200s` (32×3600)  
- **最大湿润时间**：16h 作物 = `19200s` (5h20m)，32h 作物 = `38400s` (10h40m)  
- **浇水可用阈值**：16h 作物剩余湿润时间 ≤ 5h (`18000s`，不含等于)，32h 作物 ≤ 10h (`36000s`，不含等于)

### 约束
- 成熟后（`matureCountdown <= 0`）：不允许浇水，允许修改、删除、一键播种。
- 浇水湿润倒计时归零（`waterCountdown <= 0`）：仅视觉提示“水分干枯”，无其他惩罚，允许浇水（若满足浇水条件）。

## 3. 页面布局与交互
### 3.1 表格结构
| 列名 | 说明 |
|------|------|
| 用户 | 显示/编辑文本 |
| 作物类型 | 显示 `16h作物` / `32h作物`，编辑时下拉选择 |
| 成熟倒计时 | 显示 `HH:MM:SS`，下方小字显示浇水减少时间（若有）。<br>**高亮规则**：<br>- 剩余 ≤ 1h (`3600s`) 且 > 0：黄色预警背景<br>- 已成熟（≤ 0）：绿色背景 |
| 浇水湿润倒计时 | 进度条形式展示，剩余百分比着色：<br>- >50% 绿色<br>- 20%~50% 橙色<br>- <20% 红色<br>同时显示时间文本 `HH:MM:SS` |
| 水分干枯时间 | 绝对时间 `YYYY-MM-DD HH:mm:ss`，动态刷新 |
| 预计成熟时间 | 绝对时间 `YYYY-MM-DD HH:mm:ss`，可点击列头排序（循环切换：默认递增序号 → 预计成熟时间降序 → 默认）。列头旁有重置排序图标 |
| 操作 | 包含按钮：修改、浇水、一键播种、删除 |

### 3.2 按钮功能细节
#### 修改
- 点击后当前行进入编辑状态，冻结该行倒计时快照（记录点击时刻的 `matureCountdown` 和 `waterCountdown`）。
- 可编辑字段：用户（文本输入）、成熟倒计时、浇水湿润倒计时、作物类型（下拉）。
- 时间编辑使用两个输入框，格式 `[时]:[分]`，时框无限制（≥0整数），分框 0~59。秒数在保存时归零。
- 提交修改：
  - 若用户未改动某个倒计时输入框，则使用**快照值减去编辑期间实际流逝时间**（如果已成熟则冻结为0）。
  - 若用户改动了输入框，则直接采用用户输入的小时+分钟转换为秒。
  - 作物类型改变时，成熟倒计时和湿润倒计时均重置为满值（新类型的总时长和最大湿润时间），忽略用户修改。
- 保存后解除冻结，恢复动态倒计时。

#### 浇水
- 可用条件：对应作物湿润剩余时间 **严格小于** 阈值（16h: 剩余<5h，32h: 剩余<10h）且作物未成熟（`matureCountdown > 0`）。
- 不可用时按钮置灰，并显示 Tooltip 说明原因。
- 点击后：
  - 新湿润倒计时 = 最大湿润时间（16h→5h20m，32h→10h40m）
  - 成熟减少量 = (最大湿润时间 - 浇水前剩余湿润时间) / 4
  - 新成熟倒计时 = 当前成熟倒计时 - 成熟减少量（结果不能小于0，若小于0则置0）
- 浇水后在该行成熟倒计时下方显示小字提示：“- XXh XXm”（3秒后自动消失）。多次浇水时，提示不可重叠或替换，每次独立创建，3秒后移除自身。

#### 一键播种
- 所在行的操作按钮，点击后：
  - 该行进入编辑状态，并立即弹出作物类型选择（或直接在编辑区选择）。
  - 用户选择作物类型后，自动完成播种：设置成熟倒计时为满值，湿润倒计时为满值，然后立即执行一次浇水效果（即成熟倒计时减少 (最大湿润时间 - 0)/4 = 最大湿润时间/4，湿润倒计时仍为满值）。
  - 播种完成后显示撤销提示（如 Toast），几秒内可撤销，撤销则恢复播种前状态。
- 一键播种的“当前行”必须已存在（不能是新增空行，若为空行则视为添加行+播种）。

#### 删除
- 点击弹出二次确认，确认后移除行。

#### 添加行
- 表格上方或下方有独立“添加行”按钮。
- 点击后新增一行：`user` 为空，`cropType` 默认 `'16h'`，`matureCountdown` 和 `waterCountdown` 均为满值（16h成熟、5h20m湿润），`createOrder` 递增。
- 新行自动进入编辑模式，用户可直接修改编辑。
- 多次点击添加行时，只最后一行为编辑状态。

### 3.3 全局行为
- 所有倒计时（成熟、湿润）每秒更新一次，实时计算干枯时间与成熟时间。
- 页面刷新或关闭后重新打开，数据从 `localStorage` 读取，倒计时基于绝对时间戳恢复（数据模型存储 `matureCountdown` 和 `waterCountdown` 的秒数，但可配合上次保存的时间戳在初始化时减去流逝时间）。
- **多标签页冲突提示**：首次加载时检测，若发现 `localStorage` 数据可能被另一标签页操作，可提示用户单标签页使用。技术实现可在保存时使用时间戳版本号。

## 4. 数据持久化方案
使用 `localStorage`：
- 存储键：`crop-management-data`
- 存储内容：JSON 对象，含版本号、行数据数组（每行含所有必要字段及 `lastUpdateTime` 用于计算流逝）。
- 初始化逻辑：读取数据后，按 `lastUpdateTime` 与当前时间差，更新 `matureCountdown`、`waterCountdown`（减去流逝秒数，不低于0），然后启动倒计时。
- 任何增删改操作立即序列化保存。
- 页面关闭/刷新时数据已实时存储。

---

## 5. 导入导出
- **导出**：按钮点击后，将当前数据（含当前动态倒计时值）导出为 JSON 文件下载。
- **导入**：提供文件选择，读取 JSON 文件并覆盖当前数据，刷新表格。导入时做基本格式校验。导入后需要将导出至导入之间的时间计算到成熟时间、湿润时间。

## 6. UI/UX 要求
- 商业级 CSS 设计，简洁现代，使用细微阴影、圆角、合理间距。
- 进度条平滑，颜色过渡。
- 表格行高亮状态清晰。
- 移动端：表格可横向滚动，操作按钮区域扩大，保证触控友好。
- Tooltip、确认弹窗、Toast 提示样式统一。
- 浇水减少时间小字使用淡色、较小字号，出现在倒计时数值下方，带渐隐动画。

---

## 7. 技术约束
- 纯前端实现，HTML + CSS + JavaScript（可配合现代框架如 React/Vue 或原生）。
- 不使用后端，无网络请求。
- 注意性能：使用 `setInterval` 或 `requestAnimationFrame` 更新，确保百行内无压力。
