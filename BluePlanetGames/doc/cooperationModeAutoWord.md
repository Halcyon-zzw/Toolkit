
## 功能名称：小游戏自动词条选择脚本

### 一、界面与控制逻辑

- 在页面**左下角**新增一个按钮，初始显示文字为“**开始**”。
- 点击“开始”后，按钮文字变为“**停止**”，并启动主流程循环。
- 点击“停止”后，立即终止所有正在运行的线程和循环逻辑，按钮恢复为“开始”状态。
- 未点击“开始”前，不允许任何后台线程或定时任务执行。

---

### 二、主流程逻辑（循环执行）

**主循环周期**：每 `10` 秒执行一轮（该间隔应支持配置）。

每轮主流程中，执行以下子循环（**最多重复 3 次（可配置）**）：

#### 子循环步骤说明：

**步骤 1：打开词条选择界面**
- 点击【选择词条按钮】，所在区域坐标范围为：
  ```
  (240, 2200, 370, 2300)
  ```

**步骤 2：OCR 识别当前可选词条**
- 进入词条选择页面后，对以下区域进行 OCR 文字识别：
  ```
  (80, 750, 990, 830)
  ```
- 期望识别出 **3 个词条名称**。

**步骤 3：判断是否需要刷新**
- 如果识别出的 **3 个词条** 均 **不包含在** `needWordList` 中：
    - 点击【刷新按钮】，所在区域为：
      ```
      (400, 1500, 680, 1600)
      ```
    - 再次执行 **步骤 2** 重新识别（注意不是跳回步骤2，因为只能点击一次刷新）。

**步骤 4：选择词条**
- 如果识别出的 **3 个词条** 中，**至少有一个** 存在于 `wordList` 中：
    - 优先选择 **`wordList` 中靠前** 的词条。
    - 可点击的 3 个词条位置分别为：
      ```
      词条1：(80, 1100, 300, 1300)
      词条2：(430, 1100, 650, 1300)
      词条3：(770, 1100, 990, 1300)
      ```
    - **只允许选择一个词条**。
      **步骤 5：退出条件**
- 如果识别出的 3 个词条中，**没有任何一个** 存在于 `wordList` 中：
    - **直接退出子循环**，不进行任何点击操作。
    - 等待下一个主循环周期。
注意：needWordList、wordList的配置格式为'英雄名:词条名'（为了方面开发人员识别）, 获取needWordList、wordList前需要将英雄名去除。

### 四、补充说明

- 所有 OCR 识别建议增加异常处理（如识别失败、返回不足 3 个词条），避免流程中断。
- 每个动作之间建议加入短暂延时（例如 0.5~1 秒），提升稳定性。
- 停止按钮需能 **立即中断正在等待或休眠中的线程**，建议使用事件标志或线程中断机制。
- 在左上角用合适大小的透明框显示关键日志，日志框支持收起。
- 所有点击逻辑采用随机区域点击
